# C5 Remediation Plan — HealthCare audit 2026-09-16

Strategy: land the already-coherent branch-availability work first to protect the dirty tree, then remove production breakage and public/security misrepresentation before deeper clinical/admin improvements. Each phase is independently shippable, keeps Vietnamese user copy and medical safety disclaimers intact, reads all credentials from environment only, and adds regression tests rather than weakening gates. The plan uses the packet as the evidence boundary and avoids inventing new product features beyond fixing the audited defects.

## Outcome & success signal

Done means production can be deployed without demo credential exposure, broken image uploads, fake-clinician booking, private-portal dead ends, or clinically unsafe workflows; all roles (public, patient, doctor, admin) have accurate copy, correct API contracts, auditable admin/clinical actions, resilient email behavior, and a truthful TinyMCE pipeline. Measurable success: targeted regressions for every A-F bug pass, FE `node --test tests/*.test.mjs` remains 334+ passing, FE typecheck and Playwright/a11y pass, targeted backend `mvn test` passes, ai-service pytest passes for changed AI contracts, and no secret literals are introduced.

## Scope and explicit non-goals

Scope: `apps/frontend`, `apps/backend`, `apps/ai-service`, database migrations, tests, and deployment config needed to remediate A1-F4 and preserve G1. Also resolve stray untracked `apps/frontend/pnpm-lock.yaml` by deleting/ignoring only during implementation after confirming it is not intentionally used.

Non-goals: no new appointment product beyond branch availability already in G1; no real payment gateway; no new EHR/LIS integration; no redesign of the whole UI; no search-marketing campaign beyond making indexing/sitemap technically correct; no remote-LLM enablement unless product explicitly accepts cost/privacy trade-off in Phase 7.

## Risk register

1. Clinical workflow overreach: B1/B4 could grow into LIS/e-prescribing. Mitigation: implement only internal order/status/structured prescription/audit needed by packet, no external integrations.
2. Rich HTML XSS risk: fixing F2 can introduce dangerous rendering. Mitigation: server/render allowlist sanitizer, negative XSS tests, rollback flag to safe renderer.
3. Dirty tree collision: later phases could overwrite G1. Mitigation: Phase 0 commits or folds it first, then all public booking work rebases on that baseline.
4. Email outage semantics: making auth best-effort can hide delivery failures. Mitigation: durable outbox with retry/admin observability, enumeration-safe Vietnamese copy, no success claim that email was delivered.
5. Deployment config drift: F1/A1 depend on env defaults. Mitigation: startup validation, explicit production defaults, CI/config tests, no credential literals.

## Deliberately deferred

- Full LIS/specimen chain, pharmacy drug interaction engine, payment gateway, and remote-LLM expansion are deferred because the packet requires safer internal workflows and explicit product decisions, not new external integrations.
- SEO content strategy is deferred; Phase 2 only fixes robots/sitemap technical invisibility.
- Complete Spring/FastAPI cooperative cancellation may be deferred behind server-side timeout/cost guards if it proves cross-service invasive; E4 remains tracked until fully closed.
- Broad UI redesign is deferred; fixes target misleading/dead-end/a11y issues only.
