## Risk register

1. Rich-content HTML persistence can introduce XSS. Mitigation: backend sanitizer allowlist, React-safe rendering, negative tests for script/iframe/event handlers, no `dangerouslySetInnerHTML` for untrusted bodies unless sanitized wrapper is proven.
2. Clinical workflow changes can disrupt doctors. Mitigation: additive schema, feature flag, old data readable, explicit Vietnamese validation, and targeted doctor workflow tests before deploy.
3. Email degradation can create accounts without usable verification. Mitigation: outbox-first durable retry, clear pending-verification state, no transaction rollback after commit, admin observability for stuck email.
4. Demo/fake data cleanup can break demo expectations. Mitigation: non-production env flags and clear demo disclosures while production defaults are safe.
5. Multi-service chatbot contract changes can drift. Mitigation: schema contract tests at AI, Java DTO, and TS type layers in the same phase.

## Deliberately deferred

- Full asynchronous cancellation from widget close through Spring to FastAPI if it requires broad runtime refactor; E4 remains open unless a bounded token patch is safe in Phase 6.
- A full LIS/lab information system or medication interaction engine; Phase 3 adds minimum professional order/status/audit structure only.
- New branch equipment capability modeling; Phase 1 removes unsupported claims rather than inventing a capability database.
- Broad SEO/content strategy; Phase 1 fixes indexing defaults and sitemap omissions only.
- Replacing demo seed users entirely; production exposure is solved by gating UI hints and credentials while preserving non-production demos.
