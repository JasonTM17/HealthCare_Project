# C2 Remediation Plan — HealthCare digital-hospital audit 2026-09-16

## 1. Strategy
Fix the audit by risk and release boundary, not by portal silo: first preserve the coherent uncommitted branch-availability feature, then remove production-critical unsafe/broken behavior, then repair clinical/business correctness, operational durability, rich-content truthfulness, and low-risk polish. Each phase is small enough to ship independently, carries regressions for the finding it fixes, keeps Vietnamese user-facing copy, preserves medical safety disclaimers, and uses env-only configuration with no credential literals.

## 2. Outcome & success signal
Done professionally means: no public production login credential disclosure; fake/demo clinicians cannot be mistaken for real bookable clinicians; public CTAs land on valid public or auth-aware flows; doctor clinical writes are tied to the correct encounter/order model with clear validation; patient/admin contracts work; auth email does not hard-fail solely because SMTP is unavailable when durable outbox exists; production rich-content image uploads work or are deliberately disabled in UI; TinyMCE published output preserves offered formatting or stops offering unsupported formatting. Measurable success: packet findings A1-F3 and G1 are closed by code plus regression tests; FE unit tests, typecheck, focused backend tests, ai-service pytest, and Playwright/a11y gates pass without weakening assertions.

## 3. Scope and explicit non-goals
Scope: `apps/frontend`, `apps/backend`, `apps/ai-service`, Render/Vercel env contract docs/config, Flyway migrations needed for audit/prescription/lab correctness, and tests covering public, patient, doctor, admin, chatbot, and TinyMCE/media flows. The branch availability work in G1 is preserved by committing it first as-is if its current tests pass; if a gate fails, fold only the minimal gate fix into Phase 0 before the remediation phases. Non-goals: no new patient-facing medical features beyond packet fixes, no provider integrations, no new payment rail, no secrets checked into repo, no SEO/content expansion beyond sitemap/indexing correctness, no full redesign, no rewrite of the AI stack, and no weakening or deleting tests to pass.

## 5. Risk register
1. Clinical workflow migration risk: adding lab orders/audit actions can affect live doctor workflows. Mitigation: nullable/additive Flyway migration, encounter-scoped server tests, deploy during low traffic, forward rollback path.
2. Email resilience masking real outages: async outbox could hide SMTP misconfiguration. Mitigation: explicit outbox status, alerts/logs, tests for disabled outbox and retry exhaustion, no raw error leaks.
3. Rich-content contract fork: sanitized HTML would increase XSS surface. Mitigation: prefer toolbar reduction; if HTML storage is chosen, require allowlist sanitizer, regression tests for forbidden tags/attrs, and security review.
4. Demo-data handling may reduce useful staging demos. Mitigation: non-production flags/profiles preserve demo login and demo doctor labels outside production.
5. Remote LLM policy can affect cost/privacy. Mitigation: do not enable by default without product approval; if enabled, env-gated, logged with `cost_tier/routing_reason`, and fail-closed medical safety rules stay intact.

- Full branch capability model for equipment/imaging: A3 needs unsafe copy removed now; real per-branch equipment inventory is a new product feature and not implied by packet.
- Complete lab LIS/specimen integration: Phase 3 adds order/status correctness, not external lab integration.
- Full AI server-side cancellation across synchronous generation: E4 is open; implement best-effort abort and document residual worker cost unless a larger async generation architecture is approved.
- SEO content strategy and marketing copy expansion: Phase 2 fixes indexing/sitemap correctness and placeholders only.
- Sanitized-HTML article storage rewrite: defer unless stakeholders require preserving unsupported TinyMCE styles after seeing the safer toolbar-alignment option.
