## Risk register

1. Clinical data model changes overreach. Mitigation: additive nullable migrations, encounter-scope first, order lifecycle minimal, targeted clinical tests before UI polish.
2. Upload fix exposes unsafe storage or secrets. Mitigation: env-only config, startup validation, signed/validated uploads, no literals, negative tests for disabled/misconfigured storage.
3. Demo/fake doctor cleanup disrupts real booking conversion. Mitigation: preserve branch availability feature, distinguish demo vs real data, verify public booking CTAs across branch/doctor/package routes.
4. SMTP resilience hides failed patient communications. Mitigation: durable outbox/retry/audit and admin/operator visibility; user copy states to check email/SMS only after send accepted.
5. Contract propagation breaks clients. Mitigation: additive DTO fields, backward-compatible JSON parsing, run AI/Spring/FE tests in same phase before release.
