# C1 Remediation Plan — HealthCare audit 2026-09-16

## 1. Strategy
Treat the frozen packet as the scope boundary and land fixes in risk order: first preserve the coherent uncommitted availability feature, then remove production access/media/email blockers, then repair public/patient/doctor/admin workflows and finish with the TinyMCE content contract. Each phase is a small, independently shippable change set with regression tests; no credentials are literalized, Vietnamese user copy and medical safety disclaimers stay intact, and product decisions are made explicit rather than hidden in broken defaults.

## 2. Outcome & success signal
Done means production no longer exposes demo credentials, rich media upload works when storage env is configured, public pages do not misrepresent demo clinicians or private CTAs, patient/doctor/admin contracts match their backends, clinical workflows enforce safe scope/status/audit, chatbot metadata/UX is contract-complete, and TinyMCE preserves what the editor offers. Measurable success: frontend `node --test tests/*.test.mjs`, typecheck, focused Playwright/a11y, backend targeted `mvn test`, and ai-service pytest pass; each packet finding A1-F4 has a failing-before/passing-after regression or an explicit documented product decision where the packet allows it.

## 3. Scope and non-goals
Scope: Next.js frontend in `apps/frontend`, Spring Boot backend in `apps/backend`, FastAPI in `apps/ai-service`, deploy config `render.yaml`, Flyway migrations, and tests needed for A1-F4 plus G1/G2 handling. Preserve G1 by committing the branch-availability feature first as-is after its existing tests pass; if commit authority is unavailable, freeze it as baseline and fold only conflict-resolution into later phases. Remove the stray `apps/frontend/pnpm-lock.yaml` from the worktree unless the owner explicitly adopts pnpm.
Non-goals: redesigning the hospital product, adding new payment methods, building a full LIS/e-prescribing platform beyond the audited safe minimum, changing provider contracts unrelated to the findings, weakening gates, or adding secrets/credentials to code, seeds, docs, tests, or config.

## 5. Risk register
1. Auth/email change could create account flows with no delivered OTP. Mitigation: durable outbox status, retry metrics, Vietnamese support copy, and tests for SMTP-down registration/reset.
2. Rich HTML preservation can introduce XSS. Mitigation: server-side allowlist sanitizer, frontend renderer tests with malicious fixtures, no raw unsanitized body rendering.
3. Clinical workflow changes can block doctors mid-day. Mitigation: ship stricter server scoping with backward-compatible UI states, migrate data forward, and provide clear Vietnamese validation messages.
4. Demo-data cleanup can empty public catalog. Mitigation: commit G1 availability first, hide only production demo clinicians, and provide disclosed non-bookable fallback if real catalog data is sparse.
5. API contract changes can break old clients. Mitigation: additive DTO fields, temporary method compatibility for notifications, and focused contract tests across FE/BFF/BE/AI.

## 6. Deliberate deferrals
Do not build full LIS inventory, pharmacy interaction checking, insurance billing, or multi-provider AI routing beyond the audited minimum; they are larger products, not packet-required fixes. Do not enable patient remote LLM by default without explicit cost/privacy approval; the professional fix is an explicit env-governed decision plus honest UX. Do not redesign the admin CMS or public visual system beyond correcting false claims, broken links, accessibility, and SEO coverage. Do not alter unrelated academic README/demo materials except where they would expose production credentials or contradict the remediated behavior.
