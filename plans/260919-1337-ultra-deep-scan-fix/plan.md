## 4. Decisions

### D1 — Forensics before repair (Phase 1a gate)
The warm-case 12–16s failure is NOT fixed blind. Phase 1a tails Render logs for
both services (Logs API) while replaying the probe matrix, and MUST observe the
Spring-side stage the direct probes skipped: add temporary WARN logging at each
`badGateway` / citation-revalidate-null / `publicCatalogFallback`-null path in
`PublicAiChatController` (removed before merge), and record whether the 200
response carries `costTier`/`routingReason` (absence proves BFF authorship).
Prime suspects in order: citation revalidation failure against the catalog DB, a
late AI non-2xx converted to 502 by `AiService.exchange()`, stale runtime token.
The failing hop must be identified with a timestamped log line before any code
change (hard review gate between Phase 1a and 1b). Rationale: the previous session
shipped a locally-verified fix that didn't change production behavior — the same
mistake must not repeat.

### D2 — Cold-start honesty over impossible budgets (revised per Kongming)
Verified ceilings: browser abort 40s (`api-client.ts:171`), Vercel Hobby Route
Handler cap 60s, BFF public-AI timeout 35s, Spring read 35s (env-raisable via
`AI_SERVICE_READ_TIMEOUT_MS` — `boundedDuration` is a floor, not a cap), AI cold
wake 45–60s. **A full cold wake cannot traverse the chain; do not try.** The
designed contract is therefore: (a) warm-slow answers ≤35s must survive end-to-end
(fix the warm-case failure — Phase 1b); (b) a full cold start produces the
**labelled honest fallback** within the existing 35s budget, never a raw error and
never a dead 40s+ wait; (c) wait-stage messaging is client-side timers inside one
bounded request (`useChatWaitStage.ts`) — the BFF cannot emit mid-flight signals,
so AC2's first branch is "input visibly alive", not "streaming status". Keep-alive
stays off always-on (Advisor + Kongming concurrence); Phase 6 computes cadence
**including GitHub Actions scheduler jitter** (free-runner crons slip 10–30+ min,
which defeats 15-min sleep math). Backend image redeploy MUST land before any BFF
budget change (Vercel auto-deploys — new-BFF + old-Spring is a worse intermediate
state).

### D3 — Honest fallback in the UI
When the BFF emits `local_fallback`, the FloatingHealthAssistant must label it as
an offline-guidance answer (not render it like a normal AI answer), keeping the
existing suggested-action chips. Wording phase-owned (Advisor reviews).

### D4 — Debug prints and drift ship FIRST
E6/E7 are deployed defects independent of the chatbot root cause. Phase 2 lands
them immediately as one commit, so the next repair deploy is clean.

### D5 — Probe tooling becomes repo assets
The ad-hoc `scripts/*.mjs` probes are promoted into a documented verification
toolset (`scripts/verify/` with a README), or deleted if superseded — decided in
Phase 2. `apps/ai-service/scratch-prod.env` must be gitignored (it holds real
provider credentials and is currently commitable).
